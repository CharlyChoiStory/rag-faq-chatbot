## 1. RAG가 뭔가요?

### 🔑 핵심 개념 — 도서관 사서 비유

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  [일반 AI (ChatGPT 기본)]                                    │
│                                                             │
│  사용자: "우리 회사 제품 반품 정책이 뭐야?"                      │
│                                                             │
│  AI: "일반적으로 30일 이내 반품이 가능합니다..."                  │
│       ❌ 우리 회사 정책을 모름 — 일반적인 답변만 가능              │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  [RAG AI — 우리 회사 문서를 읽고 답하는 AI]                    │
│                                                             │
│  사용자: "우리 회사 제품 반품 정책이 뭐야?"                      │
│                                                             │
│  AI가 하는 일:                                               │
│  ① 우리 회사 문서에서 "반품 정책" 관련 내용 검색                  │
│  ② 찾은 내용을 바탕으로 정확한 답변 생성                         │
│                                                             │
│  AI: "OO회사의 반품 정책은 구매 후 14일 이내이며,               │
│       미개봉 상품에 한해 적용됩니다. [출처: 고객정책.pdf]"          │
│       ✅ 우리 회사 실제 문서 기반 정확한 답변                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**RAG = Retrieval-Augmented Generation**  
→ **검색(Retrieval)** + **AI 생성(Generation)**의 결합

| 구분 | 일반 AI | RAG AI |
|------|---------|--------|
| 지식 출처 | AI 학습 데이터 (과거) | 우리 회사 실제 문서 (최신) |
| 답변 정확도 | 일반적·평균적 답변 | 우리 회사 맞춤 정확한 답변 |
| 출처 확인 | 불가능 | 가능 (어떤 문서에서 찾았는지 표시) |
| 보안 | 외부 AI에 데이터 노출 위험 | 내부 처리 가능 |
| 업데이트 | 재학습 필요 (비용 큼) | 문서 업데이트만 하면 즉시 반영 |

## 2. 기업에서 왜 RAG가 필요한가?

### 📊 기업 내부 데이터의 현실

```
┌──────────────────────────────────────────────────────────────┐
│                   기업 내부 데이터의 문제                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ▶ 직원 1명이 하루 정보 검색에 쓰는 시간: 평균 2.5시간            │
│  ▶ 회사 문서 중 실제로 활용되는 비율: 약 20%                     │
│  ▶ 신입직원이 업무 파악에 걸리는 시간: 3~6개월                   │
│  ▶ 전문가 퇴직 시 사라지는 지식: 정량화 불가                     │
│                                                              │
│  → RAG 도입 시: 검색 시간 70% 단축, 지식 보존, 24시간 응답 가능  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 🏢 업종별 활용 사례

| 업종 | 데이터 소스 | 활용 예시 |
|------|-----------|---------|
| 제조업 | 매뉴얼, 설비 도면, 품질기준서 | "3호 라인 이상 시 점검 절차는?" |
| 금융/보험 | 약관, 상품설명서, 법규 | "이 고객에게 맞는 상품은?" |
| 병원/의료 | 진료지침, 의약품 정보 | "이 약의 부작용과 주의사항은?" |
| 교육기관 | 커리큘럼, 교안, 학사규정 | "수료 조건이 어떻게 돼요?" |
| 공공기관 | 법령, 지침, 민원 양식 | "이 서류 제출 기한은?" |
| IT/스타트업 | 개발 문서, API 가이드 | "이 기능 어떻게 사용해요?" |

### 🔄 데이터 흐름 상세 (동기화 파이프라인)

```
문서 → [읽기] → [분할] → [임베딩] → [저장] → [검색 가능]

       │              동기화 파이프라인 상세              │
       └───────────────────────────────────────────────┘

       │                          │
       ▼                          ▼
  ┌─────────────────────────────────────┐

  │  - PDF/Word/Excel 파싱              │

  └────────────────┬────────────────────┘
                   │
                   ▼
  ┌─────────────────────────────────────┐
  │  STEP 2: 청크(Chunk) 분할           │
  │                                     │
  │  긴 문서                            │

  │  │ 1페이지 전체 내용 (5000자) │     │
  │  └────────────────────────────┘     │
  │             ↓ 분할                  │

## 4. 데이터 소스 연결

### 📂 주요 데이터 소스별 연결 방법

#### 4-1. Notion 연결

```
┌──────────────────────────────────────────────────────┐
│                  Notion 연결 단계                     │
├──────────────────────────────────────────────────────┤
│                                                      │
│  STEP 1. Notion Integration 생성                     │
│  → notion.so/my-integrations 에서 새 통합 생성        │
│  → API 키 발급                                       │
│                                                      │
│  STEP 2. 페이지에 통합 연결                           │
│  → 공유하려는 페이지 열기                             │
│  → 우측 상단 ··· → 연결 → 생성한 통합 선택            │
│                                                      │
│  STEP 3. 코드에서 데이터 읽기                         │
│  → API를 통해 페이지 목록 조회                        │
│  → 각 페이지의 블록(내용) 재귀적으로 읽기             │
│                                                      │
│  연결 가능 범위:                                      │
│  ✅ 일반 페이지    ✅ 데이터베이스                     │
│  ✅ 하위 페이지    ✅ 표, 목록                         │
│  ❌ 이미지 내 텍스트  ❌ 외부 링크 내용               │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 🧠 임베딩(Embedding)이란? — 핵심 개념

```
┌──────────────────────────────────────────────────────────┐
│              임베딩: 의미를 숫자로 표현하기               │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  텍스트                 벡터(숫자 배열)                   │
│  ────────               ──────────────                   │
│  "바이브코딩"    →    [0.02, -0.04, 0.08, ...]          │
│  "AI 코딩"      →    [0.03, -0.03, 0.07, ...]  ← 유사!  │
│  "김치찌개"     →    [-0.5, 0.21, -0.3, ...]   ← 다름!  │

### Q2. AI가 틀린 답변을 하면 어떻게 해요?

```
대처 방법:
1. 출처 표시 의무화 → 직원이 원본 확인 가능
2. 신뢰도 임계값 설정 → 확신 없으면 "담당자 문의" 안내
3. 피드백 버튼 → 틀린 답변 신고 → 개선
4. 중요 결정에는 반드시 원본 문서 확인 규칙 수립
5. 정기적인 정확도 평가 (월 1회)
```

### Q3. 어떤 문서를 넣어야 효과가 좋나요?

```
효과 좋은 문서:                 효과 나쁜 문서:
✅ 텍스트 위주의 문서            ❌ 이미지/그래프 위주
✅ 구조화된 내용 (표, 목록)      ❌ 스캔본 PDF (OCR 필요)
✅ 자주 묻는 내용 포함           ❌ 너무 오래된 정보
✅ 명확한 Q&A 형식              ❌ 중복 내용 많은 문서
✅ 최신 정보                    ❌ 손으로 쓴 메모
```

### Q4. 구현에 코딩 실력이 얼마나 필요해요?

```
역할별 필요 기술:

  AI 컨설턴트 (기획):
  → 코딩 불필요, 비즈니스 요구사항 정의 및 테스트
  
  프론트엔드 개발자:
  → React/HTML/CSS 기본 (주니어 레벨 가능)
  
  백엔드 개발자:
  → TypeScript/Python 중급, API 설계 경험
  
  데이터 엔지니어:
  → SQL 기본, API 연동 경험, 스크립트 작성
  
  전체 솔루션:
  → AI 바이브코딩 도구 활용 시 1~2명으로도 가능
  → Claude Code, Cursor 등 AI 개발 도구 활용
```

## 📋 부록: 빠른 시작 명령어 모음

```bash
# 1. 프로젝트 복제
git clone https://github.com/your-org/rag-chatbot.git
cd rag-chatbot

# 2. 패키지 설치
npm install

# 3. 환경변수 설정
cp .env.example .env.local
# → .env.local 파일을 열어서 API 키 입력

# 4. Notion 데이터 동기화
npm run sync:notion

# 5. 개발 서버 실행
npm run dev
# → http://localhost:3000 에서 확인

# 6. 프로덕션 빌드 & 배포
npm run build
# → Vercel, AWS 등에 배포
```
